# 綜合玩法提案：夢潮提燈行

**狀態：**玩法已由專案負責人指定為 A+B+D 融合；美術風格與實際遊戲製作仍待審核。  
**來源：**2026-11-25 專案負責人要求「合併三者，做綜合的」。

## 核心玩法

玩家扮演一位迷路的小旅人，背著口袋背包，提燈走過霧港。每個夢境房間都出現一條可視化的小徑、一個目標抽屜和有限的虛構代幣。玩家要安排代幣/物件，再選一條通往下一處光源的路；路線以動畫展示選擇帶來的結果。全程只有兩次計分互動，每關一次。

### 第一關：目標抽屜與回家小徑

- **學習目標：**零用錢有限時，先替未來目標保留一部分，再安排現在想要的花費。
- **畫面語彙：**背包內有有限代幣，房間遠處可見一盞需要累積光點才能點亮的歸途燈；抽屜槽表達「先留下」和「現在使用」。
- **單一互動：**將幾枚代幣分配到目標抽屜與當下花用槽，再選擇一條小徑確認計畫。整個操作計為一個整合互動。
- **回饋：**提燈照亮已存下的進度，路徑上的小景呈現剩餘可用代幣。錯誤時用具體後果解釋，可重試；正確且能辨識保留目標資源的理由才取得第一把鑰匙。

### 第二關：背包分散與風雨小徑

- **學習目標：**任何投資都可能有起伏或損失；把所有資源放在同一處會集中風險，分散可以降低單一結果的影響，但不能保證不會損失。
- **畫面語彙：**玩家看見多條受天候影響的小徑，路徑有各自可能的明暗結果；不是金融商品或市場預測。
- **單一互動：**把虛構光石分配至不同路徑，並選定穿越方案。此為一個整合互動，不另加額外答題。
- **回饋：**逐條展示可能情境，包含分散後仍可能遇到陰雨；說明集中風險與不確定性。正確選擇須理解分散與風險理由，取得第二把鑰匙。

## A+B+D 的融合邏輯

- **A 目標抽屜：**負責直接、可讀的預算分配與目標進度。
- **B 口袋背包：**讓有限資源成為能帶著走的具體物件，承載旅人的角色奇幻。
- **D 提燈小徑：**把選擇的後果變成故事路徑，承載探索、光影與場景轉換。
- **統一互動規則：**每關一個整合決策；收納/分配、確認路徑是同一個操作流程，不增加第二道獨立題目。

## 角色與 3D 製作方向

- **旅人角色：**原創、可辨識的非 IP 小旅人，尺寸小於房間道具；輪廓、服裝與材質在選定美術風格後鎖定。
- **核心可重用場景模組：**旅人、背包、代幣/光石、目標抽屜、提燈、可重組小徑、兩種天候/光線狀態、鑰匙道具。
- **Blender 主場景：**一個低機位、超大比例、可分區的霧港夢境場景；兩關用同一套模組換燈光、道具佈局及天候，降低製作與載入成本。
- **建議動畫：**待機呼吸/微動、提燈光脈動、背包取放、代幣吸附到槽位、路徑受光、風雨變化、正確答案鑰匙浮現、錯誤答案柔和退回。
- **技術交付：**保留 `.blend` 原始場景、角色 rig 與動作；輸出經壓縮的 `.glb` 與可在 GitHub Pages/Netlify 載入的網頁場景。WebGL/GLB 失敗時保留 SVG/CSS 後備畫面。
- **關卡/風格控制：**不得先行定色、定材質、定角色造型；三張風格圖由負責人選定後，建立同一份 style bible，供所有場景、角色、UI 插圖、材質與動畫遵循。
